# Контекст работы: решения, проверенные факты и план

Файл для передачи в новую сессию. Здесь то, что **не выводится из кода**: почему выбраны
именно эти каталоги, что уже проверено на живых запросах и о чём договорились по будущим
функциям. Устройство самого приложения описано в `README.md` — его дублировать не нужно.

Дата последнего обновления: 28.09.2026 (вечер).

## 1. Каталоги: что подключено и почему именно это

| Категория | Каталог | Ключ в `js/secrets.js` |
|---|---|---|
| Книги | Google Books | `googleBooks` (необязателен, без него работает с меньшим лимитом) |
| Фильмы, сериалы | kinopoiskapiunofficial.tech | `kinopoisk` |
| Игры | RAWG | `rawg` |

Отвергнутые варианты — **не предлагать заново без новой причины**, всё проверено живыми запросами:

- **TMDB** — у владелицы резолвится в `127.0.0.1`, то есть заблокирован на уровне DNS провайдера.
  Файл `js/provider-tmdb.js` остался в проекте, но из `index.html` не подключён (кандидат на
  удаление — если понадобится, он есть в истории git).
- **api.kinopoisk.dev** (и его новый домен `api.poiskkino.dev`) — не отдаёт CORS-заголовков,
  браузер запрос блокирует. Это другой сервис, не тот, что подключён; ключ от него не подойдёт.
- **IGDB** — не отдаёт CORS вообще, плюс требует Twitch `client_secret` с обменом на протухающий
  токен. Нужен серверный прокси. Единственное, что он дал бы, — вертикальные обложки игр.
- **Open Library** как замена Google Books — слабое покрытие русских книг, описания часто пустые
  («Преступление и наказание» — ничего), а `subjects` это тематические теги (`satire`, `Ghosts`),
  а не жанры.

Причина, по которой всё это важно: приложение принципиально **buildless** — достаточно открыть
`index.html`, никакого сервера и сборки. Любой API, которому нужен прокси, не подходит, даже если
данные у него лучше.

## 2. Проверенные факты об API

CORS проверялся запросом с заголовком `Origin`. Без него сервер может не прислать заголовки ответа —
если проверяете заново, отправляйте `Origin`, иначе получите ложное «CORS нет».

| Сервис | CORS | Примечание |
|---|---|---|
| kinopoiskapiunofficial.tech | `*` | на всех эндпоинтах, включая `/api/v1/staff` |
| RAWG | `*` | |
| Google Books | `*` | |
| Claude API | `*` | нужен заголовок `anthropic-dangerous-direct-browser-access: true` |
| Яндекс.Диск REST API | `*` | разрешает `GET/PUT/DELETE` — можно писать файл прямо из браузера |
| GitHub API | `*` | |
| WebDAV Яндекса | **нет** | отвечает 401 без заголовков, из браузера недоступен |

**Кинопоиск**

- Жанры приходят прямо в результатах поиска и уже на русском — сопоставление с чипами приложения
  лежит в `js/provider-kinopoisk.js`.
- `/api/v2.2/films/{id}/similars` — готовые качественные рекомендации. Для «Интерстеллара» выдаёт
  «Довод», «Гравитацию», «Начало», «Марсианина». Лучше подбора по жанрам.
- Подбор по жанру: сортировать **`order=NUM_VOTE`**. При `order=RATING` выдаёт мусор — детские
  мультфильмы с накрученными оценками вместо известных фильмов.
- `/api/v1/staff?filmId=` — съёмочная группа с ролями (`DIRECTOR`, `ACTOR`).
  `/api/v1/staff/{id}` — фильмография человека (у Нолана 139 работ, 18 как режиссёр).
- Лимиты бесплатного тарифа в заголовках ответа не отдаются — смотреть в личном кабинете.

**RAWG**

- Обложки **всегда 16:9** (проверено: 2580×1450, 1920×1080, 3840×2160). Это кадры, а не вертикальный
  бокс-арт. В приложении кадрируются по рамке 2:3.
- Описания **нет в результатах поиска** — только в карточке игры, отдельным запросом. Поэтому в
  `js/provider-rawg.js` есть `fetchDetails()`, который вызывается при выборе варианта.
- Описания бывают за 2000 символов. Берём первый абзац: **абзацы разделены одиночным `\n`**, пустых
  строк часто нет вовсе. Разбиение по пустой строке и по тегу `<p>` не работает — проверено.
- Жанры на английском, есть таблица соответствий. Часть жанров («Хоррор», «Роглайк»,
  «Метроидвания», «Визуальная новелла») лежит не в жанрах, а в тегах.
- Разработчик → `/games?developers={slug}` даёт другие его игры. Для Hades: Hades II, Transistor,
  Pyre, Bastion.

**Google Books**

- `zoom=3` даёт обложку 575×860 — ровно под рамку приложения с запасом на retina.
- Поле `categories` для жанров **бесполезно**: у «Дюны» и «Гарри Поттера» там только `Fiction` и
  `Juvenile Fiction`. Поэтому жанры для книг проставляются вручную — это ограничение API, не баг.
- `inauthor:"..."` ищет плохо: по «Михаилу Булгакову» выдаёт книги *о* нём. Для рекомендаций по
  авторам книги — самое слабое звено.

## 3. Решения по интерфейсу, которые легко сломать обратно

- **Обложки кадрируются, а не вписываются.** У игр раньше стоял режим «вписать целиком», отсюда были
  чёрные полосы. Класс `cover-img--contain` удалён вместе с ним.
- Если кажется, что обложка «не достаёт до рамки» — сначала проверьте сам файл постера. У постеров
  Кинопоиска белые поля часто зашиты в картинку, это их дизайн, а не ошибка отрисовки.
- **Сетка мини-обложек в папках на главной использует фиксированное число колонок** с порогами по
  ширине окна (`.folder-peek` в `css/styles.css`). Не менять на `auto-fill`: папка при наведении
  плавно расширяется, и `auto-fill` пересчитывает колонки прямо во время анимации — обложки скачком
  уменьшаются вдвое и перескакивают между рядами. Пороги привязаны к ширине окна, которая во время
  наведения не меняется, поэтому скачка нет.
- **Цвет статуса не берётся из четвёрки цветов папок.** У «Заброшено» сначала стоял сиреневый
  `#B79CF2` — и язычок пропадал на странице «Сериалы», где ровно этот цвет у фона. Поэтому цвет
  мятный `#A8E6CF`, которого нет ни у одной папки: проверено на всех четырёх страницах.
- **Примеры в `demo-data.js` дописываются в конец массива `rows`.** `id` записи — это `'demo-' + номер
  строки`, а подборки в том же файле ссылаются на эти `id`. Вставка в середину молча ломает подборки.
- **Палитра: страницы светлые, крепкие цвета — только в мелочах.** Перекрашено 28.09.2026.
  Раньше страницы «Фильмы» и «Книги» заливались насыщенными `#EC1864` и `#6077D4`, и приложение
  выглядело тёмным. Теперь цвета папок светлые (`#FFB3D4`, `#FFE066`, `#A9C0F7`, `#D3BDFA`), текст
  на всех четырёх тёмный — светлого текста на цветном фоне не осталось нигде. Насыщенные малиновый,
  синий и сиреневый никуда не делись: они ушли в обложки, фигуры и кнопки, и на светлом фоне бьют
  сильнее, чем раньше на тёмном. **Не возвращать насыщенный цвет в `THEME.c`** — именно он и делал
  страницу тяжёлой.
- **Жёлтый — `#FFE066`, а не `#FFC43D`.** Прежний читался оранжевым и тянул на себя всю страницу,
  особенно на кнопках.
- **Главный акцент — малиновый, и он же на кнопках.** На кнопках стоит `--tomato-deep` `#E0115F`:
  белый текст на фирменном `#EC1864` даёт 4.3:1 и не дотягивает до 4.5:1, а на `#E0115F` — 4.8:1.
  Глазом разницы нет, поэтому сам фирменный цвет менять не стали.
- **«В корзину» — тихая серая ссылка, красная только при наведении.** Красной она стояла вплотную
  к малиновой кнопке «Редактировать»: две почти одинаковые красные кнопки рядом, одна из которых
  удаляет.
- **Язычок «Все» — песочный `--stone` `#D5CCBD`.** Был тёмно-синий в цвет футера и утяжелял
  страницу. Малиновый вместо него не подошёл: он ярче всех статусов рядом и уже занят кнопками.
  Песочный годится тем, что у него нет собственного цвета — он не спорит ни с одной из четырёх
  страниц, ни с голубым, зелёным и тёмным у статусов, а от белого открытого язычка отличается
  теплотой. Заодно ложится на «картотечную» метафору: «Все» — это сам крафтовый разделитель.
  Тот же цвет у «Все» на странице поиска (`search.js`).
- **Цвета статусов несут смысл и берутся не из палитры папок.** Голубой `#DAF5F9` — «ещё впереди»,
  зелёный `#A5E3B2` — «получилось», тёмно-серый `#4A4E6E` с белым текстом — «остыло». Совпадение
  с цветом папки делает язычок невидимым на странице этой категории (так уже терялось сиреневое
  «Заброшено» на «Сериалах») — поэтому зелёного, серого и голубого среди папок нет и быть не должно.
  Зелёный намеренно мягкий: кислотно-зелёный — это «Золотое яблоко».
  Цвет текста на плашке задаёт `STATUS_INK`, собирает то и другое `Diary.render.statusStyle()` —
  один источник на карточки, язычки в папке и чипы в окне записи.
- **Подборка целиком правится в своём окне (`collection-modal.js`), а не в строке над листом.**
  Раньше поле для названия выезжало по кнопке в строке инструментов, записи отмечались в панели
  внутри листа, а «сохранения» не было вовсе: каждая галочка сразу меняла подборку. Непонятно было
  ни куда писать, ни чем всё заканчивается. Теперь в окне сразу видно всё: название, состав с
  поиском и кнопка «Сохранить».
  Важное следствие: **окно держит черновик**. Галочки и название живут в памяти и уезжают в
  хранилище только по «Сохранить» — новая подборка не появляется в списке, пока её не сохранили, а
  закрытие окна не меняет ничего. Не переделывать обратно на «сразу в хранилище»: именно это и
  сбивало с толку.
  Порядок строк в списке считается один раз при открытии — выбранные сверху, чтобы сразу видеть
  состав. Пересчитывать его на каждой галочке нельзя: строки будут прыгать под курсором.
- **У новой записи статус не выбран заранее.** Раньше подставлялось «Хочу посмотреть», и записи
  утекали в планы просто потому, что владелица не заметила подставленное. Теперь ни одна кнопка не
  нажата, а сохранить без статуса форма не даёт: статус нужен и карточке, и фильтрам, и счётчикам.
- **Дату спрашиваем только у «Просмотрено/Прочитано/Пройдено».** У «Хочу» её нет по смыслу, у
  «Заброшено» — по решению владелицы (28.09.2026). Уход с завершённого статуса дату стирает, иначе
  она осталась бы в записи невидимой. Но у уже сохранённой записи с датой и другим статусом (такие
  есть в демо-данных) дата переживает правку, если статус не трогали — специально, чтобы открытие
  карточки на редактирование молча не съедало данные.
- **Календарь и список месяцев — свои, в `js/pickers.js`.** Нативным `<input type="date">` и
  `<select>` выпадающую часть рисует операционная система: ни шрифт, ни цвета ей не задать, поэтому
  застилизовать их под сайт нельзя в принципе — только заменить.
  Грабля внутри: закрытие по клику мимо нельзя проверять через `ev.target.closest('.pick')` в
  обработчике на `document`. Перелистывание месяца перерисовывает панель прямо во время клика, кнопка
  успевает вылететь из DOM, и у оторванного узла `closest()` уже ничего не находит — панель
  закрывалась сама. Клики внутри помечает сама панель, `document` только читает пометку.
- **Nauryz — только в заголовках страниц.** В окне записи (и просмотр, и правка) шрифт обычный:
  там заголовок — чужое название фильма или книги, и плотный дисплейный шрифт на длинных названиях
  читается хуже. Список селекторов — в `css/styles.css` рядом с `@font-face`.
- **Описание игры приходит асинхронно.** Пока идёт дозапрос, показывается подсказка «подтягиваю
  описание…», а если запись успели сохранить раньше ответа — описание дописывается в уже сохранённую
  запись. Без этого оно просто терялось на медленном соединении.

## 4. Два дизайна: что решено и что уже отвергнуто

Переключатель «Дофаминовый / Стандартный» — в футере, выбор хранится в `localStorage` под ключом
`fiks.design`. Атрибут `html[data-design]` ставит маленький скрипт прямо в `<head>` `index.html`,
до загрузки стилей, иначе при открытии мелькал бы дофаминовый дизайн. Цвета, которые интерфейс
берёт из JS (папки, страницы, статусы), подменяет `js/design.js` — он переписывает `THEME`,
`PAGE_THEME`, `STATUS_COLOR` и `STATUS_INK` на месте, после чего `Diary.refresh()` перерисовывает
страницу. Все стили стандартного — в `css/standard.css`, под `html[data-design="standard"]`, в
основном с `!important`, чтобы не трогать дофаминовый CSS.

**Стандартный — «монохром на тёплом»:** чернила `#23201C` на бумаге (фон `#F3EFE9`, листы
`#FBF8F4`), линии 1px, скругления как в дофаминовом. Правила, которые владелица утвердила:

- **Цвета нет совсем.** Пробовали акцент терракотой, потом синим — оба отвергнуты. Выбранное
  (чипы, дни и месяцы в календаре, галочки) **инвертируется**: тёмная плашка, светлый текст.
  Активная вкладка статуса выделяется только тем, что она крупнее и светлее остальных.
- **Проверка на цвет — обязательна после любых правок стандартного.** Цвет просачивается через
  переменные дофаминовой палитры (`--tomato`, цвета статусов, подсветка поиска), поэтому все они
  переопределены нейтральными. Проверяли скриптом: обойти все страницы и окна и найти любой
  вычисленный цвет, который не тёплый серый (`r ≥ g ≥ b`, разброс не больше 26).
- **Заголовки — Lora**, ровно там же, где в дофаминовом Nauryz. Заголовки в окне записи — Onest,
  по той же причине, что и в дофаминовом: там длинные чужие названия.
- **Фигуры — тонкие контуры** тех же форм, что в дофаминовом (`OUTLINE` в `js/covers.js`),
  прозрачность около 0.35. Рисованные каракули (`.doodle`) в стандартном скрыты.
- **Рукописные подписи оставлены** («что-то новенькое!» и т. п.) — приглушёнными чернилами.
- **Обложки — бумажные листы с линейным узором**, узор выбирается по хешу названия.
- Не предлагать заново: прототип «Свечение» (отвергнут), «Пастель, минимализм» (заменён
  «Монохромом»). Прототипы удалены 28.09.2026, при необходимости — в истории git.

Грабля при проверке: смена только `#хеша` страницу не перезагружает, и дизайн, записанный в
`localStorage` из теста, не применится. Писать ключ и делать `reload()`.

## 5. Хранение данных

Сейчас `localStorage` плюс резервные копии: кнопки «Скачать копию» и «Загрузить копию» в футере,
логика в `js/backup.js`.

**Импорт сливает, а не заменяет.** Записи сопоставляются по `id`, побеждает та, у которой позже
`updatedAt`. Это осознанно: замена «в лоб» — ловушка, при которой загрузка старой копии стирает всё,
что добавили с тех пор. Удаления переносятся сами, потому что они мягкие, через `deletedAt`.

**Следующий шаг к синхронизации между устройствами — Яндекс.Диск REST API** (CORS проверен, писать
можно прямо из браузера, сервер не нужен, данные остаются в личном облаке владелицы). Свой сервер
(PocketBase на VPS в РФ) нужен только если появятся посторонние пользователи.

Засада на будущее: обложки, загруженные вручную, лежат внутри записей как base64. В `localStorage`
это терпимо, при сетевой синхронизации их надо выносить отдельными файлами.

### Юридическое (пользователи из РФ)

- Пока приложением пользуется только владелица, **152-ФЗ не применяется вообще** — по ст. 1 ч. 2
  обработка физлицом для личных нужд выведена из-под закона. Ни уведомления в РКН, ни локализации,
  ни политики обработки не нужно.
- Всё это включается в момент появления посторонних пользователей. Тогда обязательны: локализация
  (первичное хранение только на серверах в РФ, ст. 18 ч. 5), уведомление РКН до начала обработки,
  опубликованная политика обработки, уведомление об утечке в течение 24 часов.
- Не добавлять обмен сообщениями между пользователями — это переводит сервис в разряд организаторов
  распространения информации с отдельными тяжёлыми обязанностями.

## 6. План функций: о чём договорились

Порядок важен — каждый следующий шаг опирается на предыдущий.

**Шаг 1. Статус «Заброшено»** — **сделан 28.09.2026.**
Одно слово «Заброшено» на все четыре категории, ключ `dropped`, цвет `#A8E6CF`.
Считается **отдельно**: не попадает ни в «просмотрено», ни в «в планах».
Что тронуто: `constants.js` (ключ, подписи, цвет), счётчик-стикер «N заброшено» на главной
(`home.js`, показывается только когда их больше нуля), строка под заголовком папки (`category.js`),
четыре записи-примера в `demo-data.js`. Язычки-фильтры в папке, чипы статуса в окне записи и
плашка на карточке строятся из `STATUS_KEYS` и подхватили статус сами — правок не потребовали.
`footer.js` тоже не правился: он считает все записи и корзину, а не статусы.
Старые записи переживают добавление: миграция в `repository.js` сбрасывает на `planned` только
статусы, которых нет в `STATUS_KEYS`, а `dropped` там теперь есть — проверено перезагрузкой.

**Шаг 2. Дашборд и календарь** — не начат, на паузе, пока не дадут команду делать.
Новая вкладка в шапке, маршрут добавляется в `state.js:6`. Статистика по категориям: сколько всего,
по статусам, средняя оценка, распределение оценок, любимые жанры, разбивка по годам.
Календарь: **основной вид — месяц с перелистыванием ‹ ›, плюс переключатель «весь год»**.
Показывает только законченное и заброшенное; запланированное не показывает, потому что дата у записи
в планах означает «когда собираюсь», и смешивать это со статистикой было бы враньём.
Оговорка с 28.09.2026: форма теперь спрашивает дату только у завершённого, так что у новых
заброшенных записей даты не будет и в календарь они не попадут — только те, у которых дата осталась
с прежних времён. Если заброшенное в календаре всё-таки нужно, надо вернуть поля даты этому статусу.
Заготовку календаря можно взять из `js/pickers.js` — он уже месячный, с ‹ › и неделей с понедельника.
Засада: дата бывает трёх видов — точная, примерная (год или год+месяц) и «без даты». На конкретный
день кладётся только точная, остальные нужно выносить отдельной строкой под календарём.

**Шаг 3. Сбор людей в записи** — не начат, на паузе, пока не дадут команду делать.
Сейчас в записях **не хранятся** режиссёры, актёры и разработчики, а без них рекомендации по людям
не посчитать. Нужно: добавить поле в запись, заполнять его при добавлении из каталога дополнительным
запросом (как уже сделано для описания игр) и сделать разовое дозаполнение для существующих записей
по сохранённому `source.externalId`. Записи, заведённые руками без выбора из каталога, останутся без
людей — для них функция работать не будет.

**Шаг 4. Рекомендации** — **отложены по решению владелицы (28.09.2026)**, вернуться позже.
Договорились на гибрид: каталоги дают кандидатов («похожие» от Кинопоиска, игры по жанрам и
разработчикам), Claude ранжирует и объясняет выбор. Технически проверено, что Claude API вызывается
прямо из браузера. Нужен ключ Claude API, его пока нет. По умолчанию модель `claude-opus-5`
(~4–8 центов за обновление); выбор модели за владелицей, не удешевлять за неё.
Отдельный раздел внутри рекомендаций — по людям (шаг 3): «вам нравятся фильмы этого режиссёра».

**Шаг 5. Деплой на облачный сервер** — не начат, в планах (добавлено 28.09.2026).
Сейчас сайт публикуется на GitHub Pages: workflow `.github/workflows/pages.yml` выкладывает
репозиторий при каждом пуше в ветку. Этого хватает для показа, но у Pages два ограничения:
- **Ключи каталогов.** `js/secrets.js` в репозиторий не попадает, поэтому на Pages поиск по
  Кинопоиску и RAWG не работает. Положить ключи в публичную статику нельзя — их увидит любой.
- **Нет серверной части.** Без неё недоступны IGDB и всё, что требует прокси (см. раздел 1), и нет
  общего хранилища для синхронизации.

Что нужно от облачного сервера: отдать ту же статику (сборка по-прежнему не нужна) и тонкий
серверный прокси к каталогам, который держит ключи у себя. Тот же сервер потом станет местом для
синхронизации (PocketBase, раздел 5) и для ключа Claude API под рекомендации (шаг 4) — ключ
тоже нельзя отдавать в браузер на публичном сайте.
Выбор провайдера за владелицей. Если сервером будут пользоваться посторонние, данные должны
храниться в РФ (раздел 5, «Юридическое») — это сразу сужает выбор до российских облаков.
Приложение должно продолжать открываться и как файл `index.html` без сервера — прокси только
добавляет возможности, а не становится обязательным.

## 8. Как проверялась работа

Приложение статическое, поэтому проверка — поднять локальный сервер и прогнать сценарии в браузере:

```
python -m http.server 5173
```

Дальше Playwright (ставился в отдельную папку, в проект не добавлялся) — клики по реальному
интерфейсу, скриншоты, чтение `localStorage`. Все описанные выше факты об API получены живыми
запросами, а не из памяти: в этом проекте несколько раз оказывалось, что «очевидное» допущение
неверно — заблокированный домен, отсутствующий CORS, редирект, ломающий preflight. **Проверяйте
допущения запросом, прежде чем строить на них план.**

## 9. Стиль кода

Код намеренно на ES5: `var`, `function`, без стрелочных функций и классов (исключение — `covers.js`).
Сборки нет, модули складываются в `window.Diary` и подключаются по порядку в `index.html`.
Комментарии пишутся там, где неочевидно **почему**, а не что делает код. Интерфейс общается только
с репозиториями, репозитории — только с адаптером хранилища.
